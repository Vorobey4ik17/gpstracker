СИСТЕМА ИЗ ДВУХ СЕРВЕРОВ (500+500, единый организм)
====================================================

АРХИТЕКТУРА (активный + горячий резерв):

  Телефоны (500+)                Телефоны (500+)
        |                              |
        v                              v
   ГЛАВНЫЙ СЕРВЕР  ----Litestream--->  РЕЗЕРВНЫЙ СЕРВЕР
   (принимает точки,  (база копируется  (та же карта, та же
    единственный        непрерывно,      база; только читает;
    источник правды)    задержка ~1 сек)  ждёт своего часа)
        |
   Плавающий IP + домен gps.вашдомен.ru
        |
   Диспетчерская карта

Почему не два активных: два сервера, пишущих в одну базу,
требуют PostgreSQL + сложную синхронизацию — неделю работы и
новые точки отказа. Схема "активный + копия" даёт то же самое
"единое существо" с задержкой репликации 1 секунду.

ЖЕЛЕЗО:
  Главный:  4 vCPU / 8 ГБ RAM / 80 ГБ SSD  (Hetzner CX32 ~€8.5/мес)
  Резерв:   2 vCPU / 4 ГБ RAM / 40 ГБ SSD  (Hetzner CX22 ~€4.5/мес)
  Опция:    Floating IP (~€3.5/мес) — для автоматического
            переключения за секунды. Без него — вручную
            переключить A-запись DNS (~5 мин простоя).

НАСТРОЙКА:

1. Оба сервера ставятся ПОЛНОСТЬЮ одинаково по README_DEPLOY.txt
   (питон, caddy, gps.service, wg-setup.sh — WireGuard на обоих).

2. На ГЛАВНОМ — репликация базы:
   curl -fsSL https://github.com/benbjohnson/litestream/releases/download/v0.3.13/litestream-v0.3.13-linux-amd64.tar.gz | tar xz
   mv litestream /usr/local/bin/
   # файл deploy/litestream.yml -> /etc/litestream.yml (впишите IP резерва)
   ssh-keygen; cat ~/.ssh/id_rsa.pub >> (authorized_keys на резерве)
   litestream replicate &   (или systemd-юнит)

3. На РЕЗЕРВНОМ — непрерывное восстановление копии:
   apt install litestream (или бинарь как выше)
   mkdir -p /opt/gpstracker
   litestream restore -o /opt/gpstracker/gps.db sftp://root@ГЛАВНЫЙ/opt/gpstracker-replica
   # дальше: litestream restore -continuously (systemd-юнит litestream-restore)
   # сервер на резерве работает с репликой базы и показывает ту же карту

4. ПЛАВАЮЩИЙ IP (Hetzner):
   console.hetzner.cloud -> Floating IPs -> создать, привязать к главному
   DNS: A-запись gps.вашдомен.ru -> ПЛАВАЮЩИЙ IP (не IP сервера!)
   Токен API: Security -> API Tokens -> создать (read+write)

5. АВТОПЕРЕКЛЮЧЕНИЕ: deploy/failover.sh на резерве:
   chmod +x failover.sh
   crontab -e -> добавить: * * * * * /opt/gpstracker/failover.sh >> /var/log/failover.log 2>&1
   (впишите IP, плавающий IP, токен в начале скрипта)

6. ВПРАВОЧКА ПЕРЕД ИГРОЙ:
   - выключите главный -> через ~15 сек карта должна открываться
     с резервного (тот же домен, те же точки)
   - включите главный обратно, верните IP

ЧТО ВИДИТ ИГРОК при падении главного: ничего. Телефоны копят
точки в буфер (есть в приложении), переподключаются на резерв,
карта на диспетчерском ПК продолжает рисоваться с той же базы.
